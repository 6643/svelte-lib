# svelte-builder 重写设计

## 目标

把 `src/builder/` 重写成更小、更直接的实现，优先优化内部结构、错误处理和安全边界，减少维护旧结构的成本。

这次重写允许：

- 收敛对外导出
- 收敛少量配置语义
- 删除不再需要的兼容垫片和中间 helper

这次重写不追求：

- 保持当前内部文件结构
- 保持所有旧 helper 的公开可见性
- 为历史形态保留复杂兼容分支

## 核心原则

1. 单一职责优先
2. 结果对象显式传递，避免隐式状态
3. 路径和文件系统操作集中到边界层
4. 错误路径和正常路径一样认真对待
5. 公开 API 只保留真正需要给外部用的部分

## 方案

### 1. API 收口

把 `src/builder/_.ts` 收紧为少量稳定导出，只保留：

- CLI 入口
- `build` / `dev` 的主入口
- 必需的配置定义助手
- 少量确实有外部消费价值的类型

移除或不再对外导出的内容：

- 内部验证函数
- 路径解析 helper
- 请求路由 helper
- 编译/发布流水线的中间步骤函数

### 2. 配置收口

配置只保留真正有效的字段和默认值，语义统一：

- `builder.ts` 作为唯一配置入口
- 配置文件按 TypeScript 语法加载
- 只接受结构化默认导出对象
- 旧配置格式不再保留
- 不再容忍历史字段别名

配置层负责：

- 读取
- 字段校验
- 默认值注入
- 项目根和源码根推导
- `appComponent` / `assetsDirs` / `outDir` / `mountId` 的边界校验

### 3. build 流水线重写

`buildSvelte()` 改成分段流水线，但保持在 `build.ts` 内部，不继续拆成零碎模块。

阶段建议：

1. 解析配置
2. 验证路径和源码树边界
3. 准备临时目录和输出目录
4. 执行 `Bun.build`
5. 后处理 JS / CSS
6. 写入 HTML shell
7. 复制静态资源
8. 原子化发布或失败回滚

要求：

- 每一步只返回一个 `Result`
- 临时文件和临时目录统一清理
- 文件 I/O 错误要带上下文
- `Bun.build` 失败要保留原始诊断

### 4. dev 服务器重写

`dev.ts` 只保留：

- 服务启动
- 请求分发
- SSE / reload 连接
- 配置重载入口

模块加载、编译缓存、路径解析、watch 事件分类应收敛成少量内部函数，避免把路由逻辑和编译逻辑混在一起。

要求：

- 请求路由按路径类型分层
- 资源请求和源码请求分开处理
- 文件监听错误有明确日志
- 配置变更可触发 reload
- 模块加载必须继续遵守本地源码边界

### 5. 安全边界

必须覆盖：

- 路径穿越
- 符号链接逃逸
- TOCTOU 风险
- 临时文件泄露
- 输出目录和源码目录重叠
- 本地源码导入越界

建议把这些校验集中到几个明确边界：

- 配置加载边界
- 源码树解析边界
- 资产路径解析边界
- 发布边界

### 6. 测试补强

当前测试优先补这些空洞：

- 配置加载的 TS 语法支持
- 错误配置与缺失字段
- `buildSvelte()` 的失败路径
- 临时目录清理
- 资产目录重叠和越界
- dev 请求路由分支
- watch 事件分类和 debounce
- SSE 响应结构
- 公开导出是否过多

## 预期结果

重写后 `src/builder/` 应该呈现为：

- 更少文件
- 更少公开 helper
- 更平的控制流
- 更集中的安全检查
- 更容易覆盖测试
